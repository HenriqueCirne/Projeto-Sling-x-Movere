**Decisões de arquitetura relevantes para o @qa** (detalhamento em `.ai/decision-log-1.1.md`):

- **`prisma/` na raiz do monorepo**, não em `packages/web/`: o CLI do Prisma resolve `.env`
  pelo cwd — com o schema na raiz não é preciso `--schema` nem um segundo `.env`. O banco
  também é infraestrutura compartilhada (o job de sync da Story 1.4 pode não morar em `web`).
- **`.env` único na raiz**, mantendo o padrão das variáveis `MOVERE_API_*` exigido pela
  story. Como o Next.js carrega `.env` do diretório da aplicação, `next.config.ts` usa
  `loadEnvConfig(monorepoRoot)` do `@next/env` como ponte. O `docker-compose.yml` lê o mesmo
  arquivo nativamente. Evita dois `.env` fatalmente dessincronizados.
- **Health-check degrada, não quebra:** `PrismaClient` é instanciado preguiçosamente e o ping
  fica em try/catch. Sem banco, a aplicação **sobe** e reporta `degraded`, em vez de derrubar
  justamente a página que existe para diagnosticar o problema.
- **NFR4 / segurança:** o erro bruto do Prisma pode conter a connection string com senha —
  ele é logado no servidor e **nunca** chega à camada de apresentação. Há um teste que falha
  se `postgresql://` aparecer no relatório. O `docker-compose.yml` **não** define senha
  padrão: usa `${POSTGRES_PASSWORD:?...}`, falhando com mensagem clara em vez de subir um
  banco com credencial versionada. Confirmado no HTML renderizado: 0 ocorrências da
  connection string e da senha.
- **`export const dynamic = 'force-dynamic'`** na página: sem isso o Next pré-renderiza o
  health-check no build, o que exigiria banco de pé no CI e congelaria um status que precisa
  ser lido em tempo real. Build confirma `/` como `ƒ (Dynamic)`.
- **Escopo de dependências:** instaladas apenas as exigidas pela Task 1 (next, react,
  react-dom, typescript, tailwindcss, zod) + Prisma + Vitest. Zustand, React Query, React
  Hook Form, Playwright e MSW constam do preset mas **nenhuma AC desta story os exige** —
  entram na story que primeiro os usar.
- **Ajustes no scaffold:** removidos `next/font/google` (faria o build depender de rede — ponto
  de falha gratuito no CI da AC4), os 5 SVGs não referenciados de `public/` e o `README.md`
  boilerplate do create-next-app (substituído pelo README da raiz). `AGENTS.md` e `CLAUDE.md`
  de `packages/web/` foram **mantidos**: o `next dev` os reescreve a cada execução, então
  removê-los só produziria diff sujo recorrente.

**L1 — LIMITAÇÃO DE AMBIENTE: Docker não instalado nesta máquina** (`docker --version` →
command not found). Consequência: o `docker-compose.yml` foi escrito e revisado mas **não
executado**, e a migração `0_init` **não foi aplicada contra um Postgres real**. O
health-check foi validado end-to-end no **caminho de falha** (`degraded` / "Sem resposta"),
que é o comportamento correto sem banco; o caminho `connected` está coberto por teste
unitário, mas não por verificação real. **Verificação pendente para quem tiver Docker:**
`npm run db:up && npm run db:deploy` e conferir que a página exibe "Operacional"/"Conectado".

**L2 — CodeRabbit indisponível:** `wsl.exe` reporta que o WSL não está instalado, e o CLI só
está configurado para rodar via WSL. Gate pulado por graceful degradation
(`skip_if_not_installed: true`). Revisão automatizada pendente para @qa/@devops em ambiente
com WSL.

**Dívida técnica registrada:** `npm audit` aponta 1 vulnerabilidade HIGH transitiva
(`deepmerge-ts`, GHSA-ggr8-5vv4, via `prisma` → `@prisma/config`). É dependência de
**desenvolvimento**, fora do bundle de runtime, e não há correção sem breaking change no
Prisma. Reavaliar no próximo bump.
