## Story

**As a** gestor,
**I want** ver um ranking de clientes por faturamento,
**so that** eu identifique meus clientes mais valiosos (Requisito 5).

## Acceptance Criteria

1. Lista de clientes ordenada por faturamento total, decrescente.
2. Filtro por período.
3. Exibe posição/rank e valor faturado por cliente.

## Tasks / Subtasks

- [ ] Task 1: Query de ranking (AC: 1, 3)
  - [ ] `groupBy({ by: ['cliente'], _sum: { valorTotal: true }, orderBy: { _sum: { valorTotal: 'desc' } } })`, excluindo `cliente: null`
  - [ ] Posição/rank é o índice do array ordenado (+1) — calculado na camada de serviço, não no banco
- [ ] Task 2: UI da lista/tabela (AC: 1, 3)
- [ ] Task 3: Filtro de período (AC: 2) — reutilizar componente compartilhado
- [ ] Task 4: Testes e validação
  - [ ] Testes unitários do ranking (ordenação + numeração de posição) com repositório fake
  - [ ] Confirmar `npm run lint`, `npm run typecheck`, `npm test`
  - [ ] Atualizar File List

## Dev Notes

**File Locations**: `packages/web/src/features/reports/ranking-clientes/`.

**Technical Constraints**: `cliente` nulo é excluído do ranking (não faz sentido rankear "cliente não informado") — diferente de 2.2/2.5, que agrupam nulos sob rótulo explícito. A diferença é deliberada: aqui o nulo não é uma dimensão do relatório, é ausência de dado que invalidaria a posição no ranking.

**Dependencies**: Depende da Story 1.3.

### Testing

- **Cenários mínimos**: ordenação decrescente por faturamento, posição 1-based correta, cliente nulo excluído do ranking (não aparece como linha).
